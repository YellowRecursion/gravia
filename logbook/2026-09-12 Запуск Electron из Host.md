# Запуск Electron из Host

Владелец предпочитает проверять сценарии через UI, но отдельно попросил пока не
создавать первый экран. Согласован минимальный каркас: Run у Gravia.Host открывает
пустое окно Electron, закрытие окна и остановка Host завершают приложение целиком.
Последнее уточнение: фронтовые библиотеки пока не ставить, архитектуру обсудить позже.

Самый простой вариант — вручную запускать Electron и backend двумя командами.
Он не отвечает требованию единой кнопки Run и оставляет вопрос владения процессами.
Выбран Host как владелец: сначала локальный HTTP listener на динамическом порту,
потом дочерний Electron и короткий handshake готовности. Изначально для передачи
URL и обнаружения смерти родителя рассматривался stdin; реальный эксперимент
ниже потребовал заменить его отдельным named pipe. Это не решение о протоколе плагинов.
Нормальная остановка закрывает pipe и ждёт Electron, после 5 секунд допускается
завершение принадлежащего Host дерева процесса. При аварийном завершении родителя
Electron видит EOF и самостоятельно завершает приложение.

Добавлен Gravia.Desktop как npm-проект с Electron 44.3.0 (стабильный npm dist-tag
latest на момент проверки), без UI-зависимостей. Node 24.12.0/npm 11.6.2 установлены
на машине; пакет требует Node >=22.12.0. Electron 44 загружает runtime лениво при
require('electron'), поэтому сборка включает отдельную проверку runtime после npm ci.
Простого наличия node_modules для этой версии недостаточно.

Host переведён на Microsoft.NET.Sdk.Web; лишний Microsoft.Extensions.Hosting
PackageReference удалён после диагностического NU1510. Application/Domain не менялись.
Используется существующая общая классификация ошибок и новый HTTP-адаптер
ProblemDetails. Конкретных предметных endpoint нет: доступны только два статических
ресурса пустой оболочки. Первичное отображение не выбрано за владельца.

Официальные основания и воспроизведение — в [README Desktop](../src/Gravia.Desktop/README.md).
Из настроек безопасности включены sandbox/contextIsolation, отключён Node renderer,
запрещены навигация, новые окна, webview и разрешения. Loopback не объявлен заменой
будущей авторизации API. Для упаковки и других ОС пока нет проверенной поставки.

При первой установке Node-загрузчик Electron завис на официальном release asset.
Использован curl к тому же GitHub URL; архив проверяется по SHA256 из установленного
пакета Electron и помещается в стандартный cache установщика. TLS и проверка
контрольной суммы не отключались, стороннее зеркало не использовалось.

## Проверка настоящего окна и корректировка канала

С stdin Electron на Windows завершался до handshake с ранним EOF, несмотря на живой
Host. ELECTRON_NO_ATTACH_CONSOLE не исправил этот сценарий. Проверен [исходник
Electron 44.3.0](https://github.com/electron/electron/blob/v44.3.0/shell/app/electron_main_win.cc)
с инициализацией stdio; отказ не выдаётся за универсальное свойство всех версий.
Контрольная связь заменена на .NET NamedPipeServerStream + Node net.createConnection:
одно подключение, случайное имя, CurrentUserOnly. Путь для Unix передаётся абсолютным,
что поддерживается [PipeStream.Unix .NET 10](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.IO.Pipes/src/System/IO/Pipes/PipeStream.Unix.cs).
Windows stdout/stderr теперь используются только для диагностики, не для handshake.

Выполнены `dotnet build Gravia.slnx --configuration Release --no-restore -warnaserror`
(0 предупреждений/ошибок), `dotnet test Gravia.slnx --configuration Release --no-restore`
(76 тестов) и `npm test` (10 тестов). `npm run smoke` проверил два сценария на Windows:

- close-window: настоящее видимое окно, пустой body, sandbox/contextIsolation включены,
  Node.js недоступен renderer; window.close завершил Host с кодом 0 и 4 процесса Electron.
- kill-host: после принудительного завершения только родительского Host окно и все
  4 процесса, перечисленные Electron app.getAppMetrics, завершились самостоятельно.

Smoke запускался из временного рабочего каталога, использовал реальные Host и
Electron, а оболочку копировал из производственных исходников. Временные тестовые
каталоги удалены, исходники не затрагивались. Это не проверка установщика или других ОС.
