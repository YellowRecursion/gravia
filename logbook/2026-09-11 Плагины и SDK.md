# Плагины и SDK

Дата: 11 сентября 2026; актуализировано 20 октября 2026. Статус: направление
и ограничения приняты владельцем; архитектура и протокол разрабатываются по шагам.
Подробный разбор и источники — в
[исследовании](../researches/Плагины%20SDK%20и%20межъязыковое%20выполнение.md).

## 11 сентября: постановка

Владелец закрывал неопределённость по созданию и добавлению плагинов, API/SDK,
разным языкам и производительности. Объём: общая система расширений, сначала
расчётные модели.

Проверена документация Dakota 6.24. Различаются модель, интерфейс и метод;
внешний драйвер обменивается файлами, direct вызывает вычислитель в памяти,
batch передаёт несколько оценок за запуск. `dakota.interfacing` скрывает часть
обмена, но слово plugin в библиотечном API не означает готовый установщик пакетов.

Приняты термины: плагин — единица установки; нода — экземпляр на схеме; модель —
вычислительный компонент. Отдельная сущность Module не нужна без требования,
которое её отличает.

Сравнены внешний CLI, вычисление внутри ядра, долгоживущие рабочие процессы и
прямой C# плюс внешний процесс. Для проверки транспорта сопоставлены JSON через
stdio и gRPC; выбор оставлен открытым до обсуждения и измерений.

Ориентир владельца — около 40 000 точек/с для суррогата, то есть 6,4 мс на
256 точек и 0,64 мс на 10% накладных расходов. Это оценка по памяти, не измерение.
Модели и Dakota не запускались.

Для примеров использованы FCC, MATLAB-риформинг и будущий блендинг. Локализация
плагинов: en/ru/…, автор обязан дать минимум один язык.

## 11–12 сентября: единицы и свойства

Владелец отверг общий словарь свойств с ручным сопоставлением и потребовал
проверить направления на разных установках, свойствах, составах и единицах.
Подготовлен разбор 36 случаев; проверены CAPE-OPEN, FMI, QUDT, IDAES, ASTM,
NIST, EIA/EPA и практики AFPM. Сделан C#-эксперимент: медианы 7 прогретых
измерений на 100 000 значений — подготовленный double-цикл 0,0431 мс,
UnitsNet 1,8309 мс, динамический enum-путь 5,106 мс, EngineeringUnits Density
84,9193 мс. Это синтетическая конверсия одной величины, не модель и не IPC.

Принято: плагины объявляют свои единицы, Gravia заранее готовит необходимые
пересчёты; тождественные операции не выполняются. Преобразование свойства,
требующее вычислительного метода, оформляется отдельной видимой нодой;
обычная смена совместимых единиц выполняется автоматически.

Эти решения относятся к OWN-11/OWN-12 и не утверждают библиотеку единиц или
формат материального контракта.

## 19–20 октября: возврат к плагинам

Владелец задал направление: гибкая система, сначала внешние процессы и Python
SDK, позднее C# и WASM; MATLAB не должен быть затруднён. Python и MATLAB-среды
поставляются с плагинами. Выбран TCP + JSON и memory-mapped files / shared memory
для больших данных. Учитывать NSGA-II и тысячи расчётов; пакетный API обязателен,
одиночные вызовы также входят в сценарий. Модели рассматриваются как
stateless-функции. Первый этап расширений — только ноды; интерфейс ноды Gravia
строит по `describe`.

Подключение и включение плагинов относятся к проекту. Путь к папке внутри проекта
хранится относительно корня. Включённые управляемые плагины запускаются при
открытии проекта и выключаются при его закрытии. Несколько копий Gravia работают
одновременно для разных проектов. Плагин — папка с `plugin.json`: ID, версия,
команда запуска.

Управляемому плагину адрес передаётся аргументом командной строки; при ручном
подключении Gravia показывает адрес. Порт выбирается заново при каждом запуске.
Обновление разрабатываемого плагина — явная кнопка: управляемый процесс
перезапускает Gravia, внешний — пользователь; после подключения вызывается
`describe`. Наблюдение исходников, hot reload и снимки не используются.

Первый проверяемый срез: подключение, `hello` и `log`, без нод. Протокол —
JSON-RPC 2.0, одно сообщение на строку UTF-8. `hello` содержит protocol/id/version;
Gravia сверяет ID и версию и при несовпадении закрывает соединение. `log`
содержит level/message; категория журнала выводится из ID плагина. Менеджер
плагинов — отдельное окно, как настройки. Сценарий проверяется на чистом Python
и через SDK; оба способа запуска, управляемый и ручной, входят в проверку.

Номинальное число оценок NSGA-II: `P + (G − 1) × O`; при `P = O = 256` и
`G = 200` это 51 200 оценок и около 200 пакетов, если популяция помещается
в пакет. Следующее поколение зависит от предыдущего и не передаётся вместе с ним.

## Открыто

Смысл `describe` и его связь с инициализацией; схема описания ноды, включая
переменное число потоков; формат и владение числовыми буферами; авторский API
SDK и проверка плагина через Gravia; MATLAB-адаптер; версии и поставка сред;
адресация при нескольких копиях Gravia; поведение при изменении исходников
во время расчёта (по указанию владельца пока не проектируется).
