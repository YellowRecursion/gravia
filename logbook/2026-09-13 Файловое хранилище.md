# Файловое хранилище

13 сентября 2026. Реализовано по последовательным решениям владельца:
общее IDataStore для документов, отдельный экземпляр с постоянной директорией
для приложения и будущей проектной сессии; без StorageScope и GUID проекта.
JSON — System.Text.Json; бинарные данные — отдельные методы с byte[].
Реализация — один FileDataStore, без DI-регистрации и системы настроек.

После добавления бинарных данных path однозначно обозначает файл: расширения
не добавляются автоматически, Exists/Delete общие. Это уточняет ранний пример
автоматического суффикса .json, сделанный до обсуждения бинарного API.

Прямая запись отвергнута в пользу временного файла рядом с целевым: ошибка
сериализации не должна уничтожать прошлый документ. При проверке на Windows
совместное чтение и повторная замена через File.Move дали отказ доступа;
File.Replace без общей синхронизации также дал нестабильное чтение байтов.
Выбран простой общий SemaphoreSlim на операции экземпляра, File.Replace для
замены и File.Move для первого сохранения. Конкурентный тест после изменения
прошёл отдельно и в общем наборе. Межпроцессная синхронизация не реализована.

Проверка: 35 новых FileDataStoreTests, всего 65 Infrastructure, 14 Domain и 25 Host
тестов прошли; в текущем Application.Tests после изменений владельца тестов нет.
Сборка с -warnaserror прошла. Тесты используют только собственные временные папки.
Контракт, ограничения и первичные источники API: [storage.md](../docs/storage.md).

По следующему запросу владельца подключён app scope: singleton IDataStore в
Infrastructure/DependencyInjection.cs, корень — ApplicationPaths.StorageDirectory.
Тест Host проверяет общий экземпляр между DI-scopes и освобождение контейнером,
не читая и не записывая пользовательские файлы. Проектная сессия не добавлялась.

После обсуждения риска перепутать app/project и отказа от magic strings владелец
согласовал enum DataStoreKey.Application. Регистрация заменена на keyed singleton;
безымянной регистрации больше нет. Host-тест проверяет внедрение через
FromKeyedServices, общий экземпляр между scopes, отсутствие безымянного сервиса
и освобождение контейнером.

### KeyValueStore

По согласованию с владельцем добавлен один KeyValueStore в Application/Storage:
GetAsync с default, SetAsync, ExistsAsync и DeleteAsync. Основа — существующий
IDataStore, документ — key-values.json. Общий механизм не знает о плагинах и scope;
приложение получает keyed singleton, проект получит собственный экземпляр в сессии.
Проектная сессия и система настроек не реализовывались.

Выбрано чтение при каждом вызове вместо кеша: нет отдельного жизненного цикла загрузки
и инвалидирования после прямых записей. Цена — чтение всего документа на операцию.
Семафор охватывает read-modify-write, чтобы параллельные изменения разных ключей
не перезаписывали друг друга. Default не записывается автоматически; несовместимый
тип и повреждение файла не маскируются. Подробный контракт — в docs/storage.md.

Проверка: dotnet test Gravia.slnx --no-restore -p:SkipDesktopRestore=true -warnaserror.
Прошли 120 тестов: 14 Application, 14 Domain, 66 Infrastructure, 26 Host.
