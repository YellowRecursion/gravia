# Архитектура фронтенда FSD

Дата: 13 сентября 2026. Статус: решение владельца заложено в код и документацию.

Владелец сообщил, что фронтенд будет преимущественно писать LLM, а дизайн и UX он
проверяет сам. После сравнения общих components/hooks/services с FSD выбран FSD;
последовало поручение «Заложи и зафиксируй архитектуру». Цель — понятные границы,
локальность изменений и автоматически обнаруживаемые нарушения. Это не задача
добавить первый экран, редактор графа или новый UI-тестовый фреймворк.

Действующие правила, сценарий и открытые вопросы:
[архитектура фронтенда](../docs/frontend-architecture.md).
Инструкции LLM: [Desktop/AGENTS.md](../src/Gravia.Desktop/AGENTS.md).
Требование отражено как OWN-26. Предыдущая проверка набора библиотек остаётся в
[записи о стеке](2026-09-11%20Проверка%20стека%20и%20границ%20реализации.md).

Перенесён существующий каркас, без добавления предметных заглушек:

- Точка входа, композиция, провайдеры и стили — app.
- Инициализация RU/EN — shared/i18n с явным index.ts.
- Orval направлен в shared/api/generated. Настоящего API/генерации всё ещё нет.
- Алиас @/ одинаков в TypeScript, Vite и ESLint. Ссылки solution обновлены.
- Pages/widgets/features/entities не создавались заранее.

Для проверки выбраны готовые eslint-plugin-boundaries 7.2.0 и
eslint-import-resolver-typescript 4.4.5, а не собственный анализатор TS. Единая
конфигурация находится в tooling/architecture.mjs и используется сборкой и тестами.
Проверяются нижележащие слои, изоляция соседних слайсов, публичные index,
неизвестные файлы/зависимости и отсутствие Node/Electron в renderer. Типовые
обходы через alias, относительный путь, import type, реэкспорт и dynamic import
проверены. Вычисляемые импорты, require и glob запрещены, так как скрывают статические
зависимости. Shared-сегменты могут взаимодействовать через свои публичные index;
специальные cross-import API сущностей (@x) пока не разрешены.

`npm run build` теперь включает lint: нарушения препятствуют и обычному Run Host.
`npm run check` включает форматирование, сборку/типы/lint и Node-тесты. Ограничения
владения состоянием не считаются доказанными линтером: Query не дублировать в
Zustand, локальный ввод оставлять в форме, рабочий документ и undo согласовать
перед реализацией. FSD не выбирает формат сохранения или API расширений.

## Фактические проверки

Среда: Windows, Node 24.12.0, npm 11.6.2, .NET SDK 10.0.302.

- `npm run check`: пройден, 43 Node-теста — 10 прежних bootstrap и 33 проверки FSD
  (11 разрешённых сценариев и 22 запрета). Тесты используют готовые файлы fixtures
  вне production renderer и настоящую политику, без отдельной имитации правил.
- Первая чистая сборка обнаружила несогласованные optional-транзитивные зависимости
  @emnapi в lockfile после установки resolver. Lockfile обновлён через
  `npm install --package-lock-only --ignore-scripts --no-audit --no-fund`;
  повторный `npm ci --no-audit --no-fund` прошёл, 399 пакетов.
- После чистой установки повторены Node-тесты и npm audit: все тесты прошли,
  найденных уязвимостей 0, включая dev dependencies.
- `dotnet build Gravia.slnx --configuration Release --no-restore -warnaserror`:
  0 предупреждений и ошибок, lint и renderer build запущены из Host.
- `dotnet test Gravia.slnx --configuration Release --no-build --no-restore`:
  все 76 .NET-тестов прошли.
- `npm run smoke`: оба сценария прошли. React монтируется, окно пустое; закрытие
  окна и принудительное завершение Host завершают по 4 наблюдаемых Electron-процесса.

Это проверка архитектурного каркаса и запуска, не полноценная проверка будущего
редактора. Linux/macOS, рабочий документ, история изменений, реальные API и
пользовательские UI-плагины в этот срез не входят.

Первичные основания: [слои FSD](https://feature-sliced.design/docs/reference/layers),
[публичные API](https://feature-sliced.design/docs/reference/public-api),
[Boundaries dependencies](https://www.jsboundaries.dev/docs/rules/dependencies/),
[настройки resolver](https://www.jsboundaries.dev/docs/settings/).
