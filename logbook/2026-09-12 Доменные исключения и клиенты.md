# Доменные исключения и клиенты

Владелец попросил изучить ошибки в соседнем td-backend, затем подтвердил обязательный
web UI и возможный MCP. После обсуждения явно запросил реализацию похожих доменных
исключений без привязки к HTTP.

В td-backend просмотрены DomainException (Status, Code, Message, Extra), middleware
перевода в ProblemDetails и Swagger-фильтр Throws. Для Gravia сохранены знакомые
Code/Message/Extra и protected Add; Status не перенесён, поскольку адаптеры могут
иметь разные протоколы. Сравнение с простым текстовым исключением и ограничения
описаны в [спецификации](../docs/errors.md). Отдельного большого исследования для
этого локального изменения не потребовалось; исходный код td — проверяемый образец.

Реализован абстрактный DomainException без новых пакетов или DI. Extra не null,
доступен через read-only обёртку; значения не копируются глубоко. Добавлена проверка
пустых кодов, сообщений и ключей. InnerException сохраняет внутреннюю причину;
транспорт не должен сериализовать объект исключения целиком.

Проверки: `dotnet test Gravia.slnx --configuration Release --no-restore` — 54 теста
прошли (14 Domain, 7 Application, 30 Infrastructure, 3 Host).
`dotnet build Gravia.slnx --configuration Release --no-restore -warnaserror` —
0 предупреждений и 0 ошибок. Тест проекции клиентских данных не является
интеграционным тестом ещё не существующего HTTP/MCP API.

Конкретные предметные исключения не выдумывались до появления соответствующих
правил. HTTP/MCP-адаптеры, обработчик транспортных ошибок и ExceptionLoggingBehavior
не добавлены. Логирование неожиданного сбоя остаётся обязанностью границы обработки,
а не доменного исключения. Требования зафиксированы как OWN-22 и OWN-23.

## Продолжение: классификация и внешняя граница Host

Владелец уточнил: доменные исключения нужны только для бизнес-логики, обычные —
аномалии, затем попросил зафиксировать это и подключить глобальную обработку.
Согласованы исключения из этого разделения: FluentValidation — ошибки запроса,
OperationCanceledException при запрошенной отмене — штатная отмена. Неизвестные
исключения и незапрошенная отмена дают internal_error, подробности только в логах.

Host сейчас консольный Generic Host. Вместо несогласованного перехода на ASP.NET
подключена реальная внешняя граница его awaited-жизненного цикла (HostProcess).
Общий ExceptionHandler зарегистрирован в DI для будущих адаптеров. Для аварии до
Build или после disposal в Main используется bootstrap-логгер в stderr. HTTP/MCP
форматы не добавлены. Это не перехват исключений всех потоков, а ошибки будущих
фоновых расчётов останутся ответственностью владельца запуска. Ограничения и
проверенное основание Microsoft сохранены в [errors.md](../docs/errors.md).

Проверка: все 70 тестов прошли (14 Domain, 7 Application, 30 Infrastructure,
19 Host). Release-сборка с -warnaserror без предупреждений и ошибок. Отдельный
процесс реального Host запущен с CapacityBytes=0: вернул 1, в stderr есть безопасный
internal_error/traceId и техническая bootstrap-диагностика ArgumentOutOfRangeException;
stdout не содержит технического исключения. Файлы и коммиты не создавались в рамках
проверочного запуска; изменение конфигурации передавалось только аргументом процесса.
