# Продукт Gravia Lab

## Название

**Gravia Lab** — полное официальное название; **Gravia** — короткое для кода
и общения. Технические имена (`Gravia.slnx`, `Gravia.Domain`, `Gravia.Host`)
сохраняют короткую форму.

## Подтверждённое описание

**Gravia Lab — расширяемая визуальная среда моделирования и оптимизации
нефтеперерабатывающего производства.**

Gravia предназначена прежде всего для оптимизации, а также для моделирования
НПЗ. Это предметная система, а не универсальный редактор графов.

- Ноды — установки, модели, преобразователи, оптимизационные блоки.
- Связи — материальные потоки и данные, по смыслу трубы между установками.
- Ядро оперирует установками, потоками, сырьём и продуктами, режимными
  параметрами, ограничениями и целями, сценариями, единицами измерения.
- Ядро не содержит конкретной химии и кинетики; компаундирование, FCC,
  риформинг и изомеризация подключаются как плагины и образуют первый
  демонстрационный контур.

## Контекст разработки

Владелец — Вадим. Около 80% разработки ведётся агентами, поэтому важны
актуальная документация, явные контракты, тесты и проверяемые критерии.
Продуктовые и архитектурные решения обсуждаются с владельцем; локальная
реализация внутри согласованного направления не требует согласования мелочей.
Диагностика и консоль — [diagnostics.md](diagnostics.md).

## Грантовый контур

Грантовая поддержка подтверждена; результаты конкурса 2027–2028 обязательны:
бензиновый контур, вектор свойств, адаптеры и суррогаты крекинга, риформинга
и изомеризации, гибридное компаундирование, NSGA-II, сценарии АИ-92-К5
и АИ-95-К5, интегрированные тесты и итоговый прототип. Решения не должны
им противоречить; при конфликте — обсудить с владельцем. Подробности —
[requirements.md](requirements.md#грант-рнф-обязательный-контур).

## Стек и общие ограничения

- .NET 10, Electron, React/TypeScript/Vite; Ant Design, Dockview, React Flow,
  i18next, TanStack Query, Zustand; ESLint, Prettier, Orval.
- Светлая и тёмная темы; интерфейс Gravia на русском и английском. Плагин
  даёт минимум один язык подписей; ID не переводятся.
- Около 80 нод — оценка масштаба схемы, не лимит.
- Кроссплатформенность предпочтительна; при трудностях допустим только Windows.
- C# — основной язык; модели могут быть на других языках.
- Пакетный расчёт обязателен; одиночные вызовы входят в сценарий. Платформа
  не распараллеливает модули автоматически.
- Для интеграции выбраны FCC и суррогат на Python, риформинг на MATLAB.
  Вызовы скрывают адаптеры. Перенос модели на другой язык допустим после
  сравнения численных результатов; необходимость MATLAB не установлена.
  Блендинг ещё не разработан.
- 40 000 расчётов/с и ускорение ~4 000× — оценки владельца по памяти,
  не измерения Gravia.

## Проект пользователя

Проект — папка с паспортом `project.gravia.json`: версия формата, постоянный ID,
название. Create/Open реализованы; сессия, сохранение изменений и UI — нет.
Контракт — [projects.md](projects.md).

## Интерфейс

FSD для фронтенда, границы защищаются ESLint; правила — в `Gravia.Desktop/AGENTS.md`,
архитектура — [frontend-architecture.md](frontend-architecture.md). Слои создаются
по необходимости; владение документом, undo/redo и UI-расширения плагинов
не определены.

## Точность расчёта

Пользователь задаёт схему, условия и задачу. Gravia передаёт модулю требование
к расчёту, включая максимальную точность; модуль сам выбирает внутреннюю модель.
Для FCC доступны кинетика, суррогат и поиск на суррогате с проверкой кинетикой.
Ядро не выбирает между реализациями. Список режимов и критерии проверки открыты.

## Единицы и преобразования

- Плагины объявляют удобные им единицы; Gravia заранее готовит пересчёт.
  Тождественная конверсия не выполняется; т/ч → kg/s — заранее подготовленное
  деление на 3,6.
- Разбор единиц и подбор конвертеров не повторяются на каждом проходе.
- Смена свойства, основы или условий, требующая вычисления, оформляется
  отдельной видимой нодой; обычная смена совместимых единиц — автоматически.
- Библиотека единиц и формат метаданных не выбраны; проверка 36 случаев
  и C#-эксперимент — [units audit](../researches/units-dotnet-audit/README.md).

## Описание потока

- Поток — дерево контекстов и свойств, например «Нефтяная часть / Частицы
  катализатора / Средний размер».
- У поля устойчивый ID; путь, название и язык не определяют идентичность.
- Определение свойства и конкретное поле различаются; соединение ссылается
  на поле. Плотность при разных температурах не требует разных определений.
- Разные плагины могут иметь разные деревья; пользователь сопоставляет
  элементы по смыслу, единицам и условиям, а не по совпадению путей.
- Свойства могут приходить из расчёта, паспорта установки/продукта или
  косвенного вычисления; отсутствие свойства в кинетическом выходе не блокирует
  интеграцию.
- Проект контракта — [material-stream-contract-v0.1.md](material-stream-contract-v0.1.md);
  он требует пересмотра и не является текущим API.

## Система расширений

- Плагины — внешние процессы; первый SDK для Python; C# и WASM предусмотрены
  архитектурно; MATLAB не затруднён.
- Плагины относятся к проекту: включаются и выключаются вместе с ним, путь
  внутри проекта хранится относительно корня. Несколько копий Gravia работают
  с разными проектами; одна папка проекта — одна копия.
- Первый этап возможностей — только ноды; интерфейс ноды строится по описанию
  плагина. Настройки приложения/проекта плагинами — позднее, без переделки
  системы.
- В проекте активно одно исследование.
- Модели — stateless-функции; поддерживаются пакетные и одиночные вызовы
  и переменное число входных потоков.
- Python и MATLAB-среды поставляются с плагинами.
- Обновление разрабатываемого плагина — явной кнопкой; автонаблюдение
  исходников и снимки не используются.
- Требования, первый срез и протокол — [plugins.md](plugins.md).

## Приоритеты архитектуры

Простые расширения, минимум путаницы, чёткие границы. Доля накладных расходов
Gravia относительно моделей не измерена. [Разбиение проектов](architecture.md) —
предложение, не утверждённая архитектура.
