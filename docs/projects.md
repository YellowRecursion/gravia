# Проект пользователя: папка и паспорт

Дата: 13 сентября 2026. Статус: **реализованы Domain, Application и файловое
хранение Infrastructure** по запросу владельца. UI и активная сессия ещё не реализованы.

## Сценарий и границы

Пользователь задаёт название и папку. Create создаёт постоянный GUID и сохраняет
паспорт; успех возвращается после записи. Open принимает папку, проверяет паспорт
и возвращает исходные ID/название. Перенос папки не меняет идентичность проекта.

Простейший вариант — писать JSON прямо в handler. Выбран IProjectStore в Application
и FileProjectStore в Infrastructure: уже принятые границы требуют оставить сценарий
независимым от сериализации и файловой системы. Application тестируется с тестовым
хранилищем; production DI всегда подключает реальную реализацию, без заглушек.

Проект — сохраняемые данные. Сессия — состояние работы редактора: открытый документ,
несохранённые изменения, история действий. Они не тождественны. Create/Open сейчас
не назначают глобальный активный проект; ownership, переключение, close и undo/redo
остаются отдельной задачей. Singleton FileProjectStore не содержит активного проекта.
Плагины в этом срезе ничего не решают; пользователь выбирает имя/папку, ядро проверяет
имя/идентичность, адаптер проверяет сохранённое представление.

## Domain

`Gravia.Domain.Projects.Project`:

- `Create(name)` — новый GUID, название.
- `Open(id, name)` — восстановление уже прочитанных метаданных с прежним ID.
- `Rename(name)` — изменение названия без изменения ID; само по себе не пишет на диск.

Название обязательно и обрезается по краям. Пустое название даёт
ProjectNameRequiredException / project_name_required; неудачный Rename сохраняет
прежнее состояние. Уникальность названия и ограничения символов пути не вводятся.
Пустой GUID в Domain.Open — ArgumentException, не бизнес-отказ. FileProjectStore
проверяет документ до вызова Domain.Open: повреждение файла не выдаётся за доменную ошибку.

Domain не содержит путь, JSON-атрибуты, версию формата, UI, runtime или активную сессию.

## Application

```csharp
var created = await sender.Send(
    new CreateProjectCommand("Оптимизация FCC", @"C:\GraviaProjects\FCC"), token);
var reopened = await sender.Send(new OpenProjectCommand(created.DirectoryPath), token);
// reopened.Id == created.Id; паспорт уже существует на диске.
```

`ProjectDetails(Id, Name, DirectoryPath)` — неизменяемая проекция для клиента,
не формат хранения. DirectoryPath — нормализованный абсолютный путь, без завершающего
разделителя (кроме корня). Относительные пути не принимаются: результат не должен
зависеть от текущей директории процесса. Имя не используется для построения пути.

Команда, валидатор и обработчик лежат в одном файле: CreateProject.cs / OpenProject.cs.
Валидаторы проверяют форму запроса, обработчики используют IProjectStore.
Они автоматически регистрируются AddApplicationServices; FileProjectStore —
AddInfrastructureServices. Host уже вызывает оба метода.

## Формат хранения v1

В папке создаётся только `project.gravia.json`, UTF-8:

```json
{
  "formatVersion": 1,
  "id": "62d1fcf1-5b9b-4205-8a37-c63ca802cc24",
  "name": "Оптимизация FCC"
}
```

DTO хранения отдельный от Domain. Чтение проверяет объект, целочисленную версию,
непустой GUID и непустое строковое имя. В v1 ровно эти три поля: дубликаты и неизвестные
поля отклоняются. Несовместимая версия не интерпретируется как v1. Поддерживается UTF-8
с BOM и без него. Open не переписывает, не чинит и не мигрирует файл автоматически.

Технический предел паспорта — 1 MiB UTF-8 на запись и чтение (включая JSON и BOM).
Ограничен фактический объём чтения, а не только предварительно проверенный размер файла.
Это защита парсинга небольшого паспорта, не лимит всего проекта, схем или результатов
и не бизнес-ограничение длины имени. При расширении паспорта предел надо пересмотреть.

## Создание и безопасность данных

- Допускается новая либо существующая пустая папка. Уже существующий паспорт и
  другие данные не перезаписываются; дополнительных каталогов не создаётся.
- Запись идёт во временный файл в той же папке через CreateNew. После записи и flush
  файл переносится в project.gravia.json с overwrite:false. Частично записанный
  временный файл не выдаётся за готовый паспорт. Конкурирующие Create не затирают победителя.
- Отмена проверяется перед операцией, при I/O и перед переносом. После успешного
  переноса отмена не превращает уже выполненное создание в отказ.
- При ошибке/отмене удаляется только собственный временный файл, если ОС позволяет.
  Созданная пустая папка может остаться: удалять пользовательскую папку небезопасно.
  После аварийного завершения может остаться временный файл; автоматического удаления
  чужих/устаревших файлов и восстановления после сбоя пока нет.
- Это не транзакция над каталогом: другие программы могут менять его одновременно.
  Проверка пустоты предварительная; эксклюзивное владение папкой не обещается.
  Стойкость к отключению питания и особенности сетевых ФС отдельно не проверены.

Основание механизма: [.NET File.Move](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.move?view=net-10.0)
описывает отказ при существующей цели с overwrite:false;
[FileStream.Flush](https://learn.microsoft.com/en-us/dotnet/api/system.io.filestream.flush?view=net-10.0)
— сброс буферов с flushToDisk. Это не основание обещать аппаратную crash-durability.

## Ошибки

Неверный Name в команде — поле name / project_name_required. Ошибки выбора папки
и проверки её содержимого — FluentValidation.ValidationException, поле directoryPath:

- project_directory_required / project_directory_absolute_required / project_directory_invalid;
- project_already_exists / project_directory_not_empty;
- project_not_found / project_manifest_invalid / project_format_unsupported;
- project_manifest_too_large / project_access_denied.

Это ожидаемые отказы проверки запроса, **не DomainException**. Сообщения безопасные,
без сырых исключений и путей. Существующий Host переводит их в validation_failed
и структурированные полевые ошибки. Неизвестный I/O-сбой остаётся аномалией;
запрошенная отмена остаётся отменой. См. [errors.md](errors.md).

## Проверки и следующий шаг

Domain.Tests защищает инварианты. Application.Tests проверяет pipeline, порт, пути,
коды и отмену без реального диска. Infrastructure.Tests работает с реальными временными
папками: roundtrip через новый DI provider, формат, перенос папки, сохранность существующих
данных, ошибочные документы, версии, ограничение размера, BOM и конкурентное создание.

```powershell
dotnet build Gravia.slnx -c Release --no-restore -p:SkipDesktopRestore=true -warnaserror
dotnet test Gravia.slnx -c Release --no-build --no-restore
```

Следующие отдельные задачи: транспортный API и UI выбора папки, сессия редактора,
сохранение изменений/ревизии/undo, схемы и подключения плагинов. Create не является Save.
Файлы блокировок и каталоги plugins/cache пока не добавляются.
