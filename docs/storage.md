# Файловое хранилище

13 сентября 2026. Реализован согласованный с владельцем базовый механизм,
не система настроек и не модель проекта.

`IDataStore` находится в Application/Storage, `FileDataStore` — в Infrastructure/Storage.
Каждый экземпляр получает постоянную абсолютную корневую директорию. Хранилище
приложения использует `ApplicationPaths.StorageDirectory`; экземпляром проектного
хранилища будет владеть проектная сессия. Хранилище приложения зарегистрировано как
keyed singleton IDataStore с ключом `DataStoreKey.Application` через AddInfrastructureServices;
DI-контейнер освобождает его
при завершении Host. Регистрация/получение экземпляра не создаёт папок или файлов.
Проектная сессия пока не реализована.
StorageScope, GUID проекта и выбор глобального текущего проекта в этом API отсутствуют.
Безымянной регистрации IDataStore нет. В конструкторе потребителя хранилище приложения
выбирается явно: `[FromKeyedServices(DataStoreKey.Application)] IDataStore appStorage`.
Хранилище проекта будет доступно через его сессию, не через этот ключ.

## Использование

```csharp
using var storage = new FileDataStore(ApplicationPaths.StorageDirectory);
await storage.SaveAsync("settings/general.json", settings);
var loaded = await storage.ReadAsync<MySettings>("settings/general.json");
await storage.SaveBytesAsync("cache/data.bin", bytes);
var exists = await storage.ExistsAsync("cache/data.bin");
```

Пользовательский компонент определяет модель данных, её бизнес-валидацию и момент
сохранения. Хранилище отвечает только за пути, сериализацию и файловые операции.
Плагины считаются доверенным кодом и могут работать с файлами напрямую вне IDataStore.

## Контракт

- Относительный path точно соответствует файлу; расширения автоматически не добавляются.
  После добавления бинарного API выбран единый способ адресации, чтобы Exists/Delete
  не угадывали, искать ли JSON или бинарный файл. Допустимы пути без расширения.
- JSON: System.Text.Json, UTF-8, форматирование с отступами, стандартные имена свойств
  и правила сериализатора. Никаких `$type`, автоматических схем или миграций.
  Публичные свойства/атрибуты и конвертеры модели определяют её сериализацию;
  произвольный объект с приватными полями автоматически сохраняемым не становится.
- ReadAsync принимает ссылочный тип документа. Отсутствующий файл возвращает null;
  повреждённый JSON, JSON null, ошибка конвертера или доступа — исключение.
  SaveAsync не принимает null. Defaults и исправление документов не делает хранилище.
- ReadBytesAsync/SaveBytesAsync читают/пишут исходные байты, без Base64 и JSON.
  Массив целиком находится в памяти; большие потоковые данные пока вне этого API.
  Переданный массив нельзя изменять до окончания записи.
- Конструктор, чтение и Exists не создают папок; Save создаёт недостающие каталоги.
  Exists проверяет файл, не каталог, и не гарантирует существование при следующем вызове.
- Delete удаляет только один файл. Отсутствие файла не является ошибкой; каталоги
  не удаляются. Никакого рекурсивного удаления через API нет.
- Save пишет уникальный временный файл рядом с целевым, сбрасывает запись на диск,
  затем заменяет существующий файл через File.Replace или создаёт новый через File.Move.
  Прямая запись проще, но могла бы повредить старый документ при ошибке сериализации.
  При отказе/отмене до замены удаляется только собственный временный файл. Если его
  удаление тоже запрещено файловой системой, он может остаться; исходная ошибка сохраняется.
- Все операции последовательны внутри экземпляра: чтение не пересекается с заменой
  файла. Это простой выбранный вариант после проверки гонки чтения/замены на Windows.
  Блокировок между экземплярами/процессами, транзакции над несколькими файлами и
  автоматических повторов нет. Внешняя конкурирующая запись/удаление может привести
  к IOException. Dispose вызывается владельцем после завершения всех операций.
- Проверяются сегменты пути: без абсолютных путей, обратных слешей, пустых сегментов,
  `.`/`..`, недопустимых символов и завершающих пробелов/точек. Существующие symlink/
  junction на проверяемом пути отклоняются. Это защита от ошибочного пути, не песочница
  против произвольных изменений файловой системы другим процессом.

## KeyValueStore

Для сценария «запомнить последний проект и прочитать его при следующем запуске»
добавлен `Application/Storage/KeyValueStore.cs`. Это удобные операции над ключами
поверх существующего IDataStore, без знания о плагинах, настройках и файловой системе.
Данные — один JSON-объект в `key-values.json` относительно корня переданного хранилища.

```csharp
public sealed class ExampleService(
    [FromKeyedServices(DataStoreKey.Application)] KeyValueStore values)
{
    public Task<string> ReadLanguageAsync()
        => values.GetAsync("gravia.language", "ru");

    public Task RememberProjectAsync(string directory)
        => values.SetAsync("gravia.lastProject", directory);
}
```

Пример не вводит обязательные ключи или автоматическое открытие проекта.
Через AddApplicationServices зарегистрирован keyed singleton с тем же
DataStoreKey.Application; он получает уже зарегистрированный IDataStore приложения.
Для проекта будущая сессия создаст `new KeyValueStore(projectDataStore)` и будет
владеть этим экземпляром. KeyValueStore не освобождает переданный IDataStore.

- Ключ — непрозрачная строка с учётом регистра, например `plugin_id.example`.
  Точки не создают вложенные объекты или папки. Уникальность имён обеспечивают потребители.
- GetAsync возвращает default только при отсутствии ключа и не сохраняет его.
  Сохранённый null остаётся null для nullable-типов. Несовместимый тип или ошибка чтения
  приводят к исключению, а не подменяются default.
- SetAsync сразу сохраняет документ; ExistsAsync учитывает ключи со значением null.
  DeleteAsync сохраняет остальные ключи; отсутствующий ключ — без записи.
- Выбрано чтение документа при каждом вызове. Кеш проще для частых чтений, но добавляет
  вопросы загрузки и обновления после прямой записи через IDataStore; пока он не нужен.
  Значения сериализуются System.Text.Json без метаданных CLR-типов.
- Один SemaphoreSlim охватывает чтение–изменение–сохранение целиком. Параллельные операции
  одного экземпляра не теряют изменения друг друга. Это не синхронизация с другим
  экземпляром, процессом или прямыми записями через IDataStore.
- Механизм предназначен для небольшого набора вспомогательных значений, не больших
  результатов расчётов: на изменение читается и сохраняется весь документ.

## Проверки и ограничения

KeyValueStoreTests: defaults без записи, JSON-типы и null, ошибки, удаление,
параллельные изменения, отмена, отсутствие кеша и DI. Интеграционные тесты проверяют
реальный файл, независимые корни и время жизни singleton; рабочие данные не затрагиваются.

FileDataStoreTests: реальные временные папки, JSON и сырые байты, отдельные корни,
вложенность, точные имена файлов, отсутствие, замена, отмена, ошибка сериализации,
неверные пути, удаление одного файла, ошибки доступа и совместное чтение/запись.
Проверка выполняется на Windows/.NET 10. Сбой питания, сетевые файловые системы и
гонки внешних процессов не тестировались; универсальная гарантия crash durability
не заявляется. Рабочие данные пользователя тесты не используют.

Основания API: [JsonSerializer.DeserializeAsync](https://learn.microsoft.com/en-us/dotnet/api/system.text.json.jsonserializer.deserializeasync?view=net-10.0),
[File.Replace](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.replace?view=net-10.0),
[File.Move](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.move?view=net-10.0).
