# Правила фронтенда Gravia Lab для LLM

Обязательны вместе с корневым AGENTS.md. Архитектура:
[docs/frontend-architecture.md](../../docs/frontend-architecture.md).
Перед изменением границ или добавлением нового слайса прочитать этот документ.

## Где писать код

- Renderer — TypeScript/React, FSD: app → pages → widgets → features → entities → shared.
- App собирает приложение; pages — экраны; widgets — самостоятельные панели;
  features — значимые действия; entities — общие клиентские представления;
  shared — непредметные средства. Entities не дублируют C# Domain.
- Сначала найти существующий модуль по назначению. Новый слайс создавать только
  под конкретное поведение, не под каждую кнопку. Не создавать пустые слои и store.
- Слайсы именовать kebab-case; React-компоненты — PascalCase. Внутри слайса ui/api/
  model/lib создавать только по необходимости; держать относящийся к задаче код рядом.
- Снаружи импортировать слайс только через его index.ts(x), с именованными экспортами.
  Внутри использовать относительные импорты, не собственный barrel.
- Запрещены импорты вверх, между соседними слайсами и в чужие внутренности — в том
  числе import type, реэкспорты и import(). Межслайсовая координация находится выше.
- App — один композиционный слой. Shared-сегменты api/ui/lib/config/i18n могут
  использовать друг друга через index. Не добавлять shared/index или features/index.
- Алиас @/ — renderer. Никаких импортов Node/Electron/shell в renderer, require,
  вычисляемых import или import.meta.glob. Не ослаблять CSP/изоляцию Electron.

## Состояние, API и UI

- Ответы Host — TanStack Query. Не копировать кеш в Zustand.
- Общее UI-состояние — в store своего слайса; состояние отдельной формы — локально.
  Для нового состояния указать владельца, время жизни и сброс при смене проекта.
- Производные значения вычислять. Выделение хранить по ID, не копией ноды.
- Владение редактируемым документом, сохранение, ревизии и undo/redo пока НЕ выбраны.
  Не принимать эти решения молча при реализации первого экрана.
- DTO генерирует Orval в shared/api/generated. Не редактировать генерацию и не
  придумывать API до согласования Host-контракта. Публичный shared/api — явные экспорты.
- Бизнес-валидация — C#. UI отображает ошибки по code/полям, не разбирает текст Message.
- React Flow/Dockview остаются в своих UI-интеграциях, не определяют формат проекта.
- Не оборачивать весь Ant и не складывать предметный код в общие utils/services.
- RU/EN через i18next, общее оформление через токены/тему; новые видимые строки
  добавлять для обоих языков. Не добавлять первый экран без задачи на него.

## Как завершать изменение

1. Проверить назначение модуля, зависимости и владельца изменяемого состояния.
2. Выполнить `npm run check` из этой папки (или `npm --prefix src/Gravia.Desktop run check`
   из корня). Это форматирование, lint, типы, сборка и технические Node-тесты.
3. После изменения shell/сборки/ресурсов: собрать Host Release и выполнить
   `npm run smoke`. Это проверка настоящего окна и завершения процессов, не UX.
4. Не выключать lint, strict, правила границ и не добавлять eslint-disable/исключения
   ради прохождения проверки. Изменение политики — сначала согласовать, обновить
   документ и положительные/отрицательные тесты архитектуры.
5. Новые UI-тестовые библиотеки не добавлять без согласования. Владелец проверяет UX
   вручную; проверки архитектуры и инфраструктуры сохранять.
