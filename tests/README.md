# Тесты Gravia

Для каждого проекта приложения создан отдельный проект xUnit на .NET 10.
Каждый тестовый проект ссылается на соответствующий проект из `src`.

FileDataStoreTests проверяет общее хранилище: JSON/байты, относительные пути,
независимые директории, отсутствие файлов, замену через временный файл, отмену,
ошибки сериализации/доступа и конкурентное чтение/запись. Все файлы — в собственных
временных папках тестов. Контракт — [storage.md](../docs/storage.md).

Проверка из корня репозитория:

```powershell
dotnet build Gravia.slnx
dotnet test Gravia.slnx
```

Application.Tests проверяет регистрацию MediatR и pipeline FluentValidation:
валидные и невалидные запросы, сбор ошибок, async-валидацию, отмену,
запросы без валидатора и передачу исключения обработчика.
CreateProjectTests проверяет DI/MediatR-команду создания проекта через тестовый IProjectStore:
постоянный ID, нормализованное название, полевую валидацию со стабильным кодом,
отмену и сохранение доменного инварианта при прямом вызове handler.
OpenProjectTests проверяет сохранение ID при повторном открытии, DI, валидацию
и нормализацию пути, сбор ошибок, отмену и передачу сбоя хранилища без подмены.
FileProjectStoreTests проверяет реальные временные папки: Create/Open через полный DI
с новым provider, формат паспорта, переименование папки, запрет перезаписи/непустой папки,
повреждённый/неподдерживаемый/слишком большой паспорт, UTF-8 BOM, отмену и гонку создания.
Host.Tests проверяет сборку, запуск и остановку Host с регистрациями Application и журнала,
переопределение размера буфера и отказ запуска при неправильной настройке.
Также проверяет ExceptionHandler и HostProcess: классификацию бизнес-отказов,
валидации, отмены и аномалий; безопасные клиентские данные, TraceId и запись в журнал;
коды завершения, синхронные/асинхронные сбои, ошибки освобождения ресурсов и вывода.
DesktopHostTests запускает настоящий локальный HTTP сервер без окна: динамический
loopback-порт, пустая оболочка, отсутствие доступа к исходникам/конфигурации и
ProblemDetails для доменных ошибок, валидации и аномалий.

Для backend CI можно заранее выполнить `npm ci` и `npm run build` в Gravia.Desktop,
затем добавить `-p:SkipDesktopRestore=true`: .NET не запускает npm и не готовит runtime.
HTTP-тесты требуют собранные веб-ресурсы, Electron executable им не нужен.
Проверки настоящих окон запускаются отдельно через `npm run smoke` в
`src/Gravia.Desktop`; условия и сценарии — в [README Desktop](../src/Gravia.Desktop/README.md).

`npm run check` в Gravia.Desktop также запускает технические Node-тесты FSD:
разрешённые импорты и намеренные нарушения слоёв/публичных API (включая относительные
пути, alias, типы, реэкспорты и lazy import), запрет Node/Electron в renderer.
Они используют ту же политику ESLint, что и обычная сборка. Это не UI-тесты;
fixtures находятся за пределами renderer и не поставляются с приложением.

Application.Tests проверяет KeyValueStore: defaults без записи, JSON-типы, null,
ошибки, удаление, параллельные изменения, отмену и keyed singleton. Infrastructure.Tests
проверяет его реальный файл и независимость корней; Host.Tests — внедрение и освобождение.

Infrastructure.Tests проверяет журнал в памяти: размер в байтах, кольцевой переход,
Unicode и усечение, снимки, повторные сообщения, счётчики, курсоры и фильтры,
Clear, 100 000 параллельных записей, ILogger/async scopes, замену через DI.
Отдельный LoggingLoadTests подаёт 2 млн сообщений от 20 источников в буфер 16 MiB.
Изолированный запуск с выводом измерений:

```powershell
dotnet test tests/Gravia.Infrastructure.Tests --configuration Release --filter "FullyQualifiedName~LoggingLoadTests" --logger "console;verbosity=detailed"
```

Domain.Tests также проверяет Project: создание/восстановление идентичности,
переименование, нормализацию и обязательность имени, неизменность при неудачной
операции; отображаемое имя не ограничивается правилами пути.
Domain.Tests проверяет LocalizedText и GraviaLanguages: основной и дополнительные переводы,
fallback на любой язык плагина, неизменяемость, замену переводов, регистр кодов,
точное сопоставление региональных вариантов, пустой текст и неверные аргументы.
LocalizedTextJsonTests проверяет автоматический System.Text.Json round-trip:
строку для текста с неизвестным языком (`new LocalizedText("Text")`) и плоский
объект переводов (`{"en":"Text","ru":"Текст"}`). Явно указанный единственный
язык сохраняется объектом; смешанные переводы, включая ключ `-`, не теряются.
Конвертер применяется атрибутом типа, в том числе во вложенных объектах с
обычными и Web-настройками. Пустой объект, пустые языковые коды и нестроковые
переводы отклоняются; JSON null допустим для необязательного текста.
Domain.Tests также проверяет Setting, IntSetting, DoubleSetting и StringSetting:
default и Reset, включительные и отсутствующие границы, сохранение прежнего значения
при отказе, неверные ограничения, NaN/Infinity и длину строки в UTF-16 без нормализации.
ChoiceSetting и SettingOption: строковые ID вместо подписей, default/Reset,
доменные отказы без изменения значения, уникальность ID, неизменяемый снимок
вариантов с сохранением порядка, локализованные названия и неверные аргументы.
Domain.Tests проверяет контракт DomainException: код, сообщение, причину, структурированные
данные, защиту словаря от внешней записи, проверку аргументов и сериализацию выбранных
клиентских данных без внутренних сведений исключения. Схемы и расчёты ещё не реализованы.
